# 計画の grill にモックを埋め込む

議論が長引く問いは、話すのをやめて使い捨てを作って見せる(Pocock の prototype)。
ただし、作り込んだ絵は判断を固定する(Shape Up、NN/g、Dow 2010)。だから段階と粗さを守る。
UI の深さが `full` のときだけ行う。

## 段階

- **ラウンド 1(範囲が決まる前)**: 絵を出さない。**文字のブレッドボード**(画面名 / その画面でできる操作 / 遷移先)を問いの本文に箇条書きで添え、「この画面と操作で足りるか」「要らない画面はどれか」を聞く。
- **ラウンド 2 以降(画面の論点が出たとき)**: 論点のある画面だけ、**粗い静的 HTML** を作る。
  - 画面の構造(何が主役か、どう辿るか)が論点なら、構造の根本から違う **2〜3 案**を作る。色違いや余白違いは案に数えない。1 案だけでは見せない。
  - 文言・項目の有無・並び順だけが論点なら **1 案** + 選択肢「直す(メモに)」。
  - 状態遷移(入力途中で戻ったら、エラー時は)が論点のときだけ、状態パネルつきの**動く HTML を 1 枚**。全画面は動かさない。全アプリのプロトタイプは別物で、本番に漂流する。
- 案の数は AI が論点の大きさで決める(ユーザー決定 2026-11-20)。迷うときは複数にする。

## 質問票での見せ方

- 案ごとに選択肢を作り、その `image` にスマホ幅(390px)のスクリーンショットを付ける。grill-visual は画像付きの選択肢を広い窓で横に並べる(最大 3 列)ので、PC では見比べられ、スマホでは縦に 1 案ずつ見られる。
- 選択肢の文は構造の違いを言葉で書く(「写真が主役のタイル。追加は右下」)。「組み合わせ(メモに)」の選択肢を最後に置く。
- モックは `~/.agent/diagrams/assets/<topic>/` に置く。原寸は 1 ページ・上部タブの `index.html`(ui-check と同じ作法)にまとめ、質問票の冒頭からリンクする。
- 問いの本文に毎回書く: 「見た目の好みではなく、何が主役か・どう辿るかで選ぶ。色・余白は後で決める。モックは使い捨てで実装には使わない」。

## 固着を防ぐ決めごと

1. 複数案を並べる。並列に複数案を見せると多様性と成果が上がる(Dow 2010)。
2. 粗さを保つ。プロジェクトのテーマは流用してよいが、磨かない。「使い捨て」と毎回明記する。磨かれた見た目は「これで本番に」を誘う(NN/g)。
3. 聞くのは配置・導線・情報の有無・操作の意味だけ。色・余白・書体は後で決める。
4. 正は言葉に置く。モックで決まった点は spec に「画面一覧・遷移・必須項目」として書き、モックはリンクで添える。実装はモックの HTML を使わず、仕様から書く。
5. モックからルールや例を起こすときは「ボタン X を押す」ではなく「ユーザーは◯◯できる」と書く。判定は「実装や画面が変わったらこの文言は変わるか」(Cucumber の指針)。
