# 凍結ファイルの形式

保存先は `<app>/docs/test-cases/<チケットslug>.md`。
ヘッダにチケット参照、seam、承認日、質問票のラウンドを書く。本文は「ルール見出し + EARS 行 + 例の表」の繰り返し。

```markdown
# <チケット名> 受け入れテストケース(承認済み)

- チケット: … / 仕様: … / seam: …
- 承認: 2026-11-20(grill `tr-<slug>` R1〜R2。高 2 件は明示採用、低 3 件は既定採用)

> **このファイルは実装フェーズで編集しない。** 変更が必要になったら実装を止めて差し戻し、
> 再承認を取ってから続ける。skip・削除・アサーションの弱体化は「完了」ではなく「失敗」。

## R1 ログインなしでは API を使えない  (リスク 高・採用)
When クッキーなしで API を呼ぶと、システムは 401 を返す

| ID | 振る舞い | 入力 | 期待結果 | 分類 |
|---|---|---|---|---|
| R1-1 | 一覧を見られない | クッキーなし `GET /api/sites` | 401 | 異常系 |

## R2 手元スイッチが入っていればログインなしで使える  (リスク 低・既定採用)
…
```

並列運用の `check-pr.sh` と凍結フックはファイル単位で見るので、この形式のまま動く。
