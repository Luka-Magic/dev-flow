# モックの作り方

| 条件 | 置き場所 |
|---|---|
| 既定(既存画面の変更、新規画面とも) | A. 開発サーバーの一時ルート |
| 開発サーバーが無い・起動できない。部品がまだ 1 つも無い | B. 単体 HTML |

大枠(何が主役か、どう辿るか)は計画の grill で粗い静的 HTML で決め終えている。ここで見るのは詳細(空の状態、エラー、必須項目、操作の結果)なので、本物の部品で見せる A を既定にする。新規画面も A で、grill で決めた構造を本物の部品で組む。

## A. 開発サーバーの一時ルート

本物の部品と CSS で見せ、「実装したら印象が違った」を防ぐ。

- チケットの作業ブランチで、`/dev/mock/<チケットslug>` のルートを 1 つ足す。中身は本物のコンポーネント + ダミーデータ(ファイル内の固定値)。API や DB は叩かない。API が要る部品は props で値を渡すか、プロジェクトに MSW 等があればそれを使う。
- 開発時だけ有効にする(`import.meta.env.DEV`、`process.env.NODE_ENV === 'development'` 等でルート登録ごと分岐)。本番ビルドに含まれないことを、ビルド結果を `mock` で grep するなどして確かめる。
- 既存画面の変更なら、各タブで before(今の本物の画面)/ after(モック)を並べる。
- 計画の grill の静的モックは構造の見本として読む。構造は変えず、HTML は流用しない。
- モックの追加は 1 コミットにまとめる(`chore(mock): <slug> の UI 確認用ルート`)。後で `git revert` で消すためである。
- 質問票からのリンクは、grill の質問票と同じくユーザーの端末から開けるホスト名にする。開発サーバーが localhost だけで待ち受けているなら、外から開けるよう起動し直す。
- プロジェクトに ui-comments(`.ui-comments/` と `packages/ui-comments/`)があれば、モックの画面上のコメントも受け付ける。判断の正は質問票の回答で、コメントは補足として読む。

## B. 単体 HTML

- `~/.agent/diagrams/assets/<topic>/index.html` に置く。静的 HTML で、実データも API も要らない。
- プロジェクトのテーマ(CSS 変数、書体、角丸)を流用して本物に近づける。
- 既存画面の変更なら、各タブの中で before / after を並べる。
- 配信は grill-visual と同じサーバー(`~/.agent/diagrams/` 配下がそのまま見える)。
- 計画の grill で作ったモックがあれば、そのファイルを起点にしてよい(構造は変えない)。
